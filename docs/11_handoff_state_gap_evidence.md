# 11 · 交接状态差异的证据（Gate E）

**结论先写：本轮没有取得"状态差异导致失败"的证据。** 下面说明为什么、现有数据能支持到哪一步、
以及下一轮最小的可证伪干预该怎么设计。

---

## 1. 三种证据的现状

| 证据类型 | 有没有 | 说明 |
| --- | --- | --- |
| ① 下游技能**独立可执行**（B0） | ✅ 有 | `place_phone_stand` 4/5、`stamp_seal` 5/5（`docs/09 §4`） |
| ② A→B **可重复的下游失败** | ✅ 有，但**只在特定 seed** | `desk_arrange 4300003`、`office_organize 4300000` 各重复 3 次（Phase 2 + 本轮 2 次）全部失败，且步数与切换点逐位一致 |
| ③ 失败交接**状态**与成功交接状态的对比 | ❌ **没有** | 失败 episode 全部发生在**没有开 trace**的运行里（Phase 2 筛查、Gate B 复查）；Gate D 的 trace 只覆盖**成功**的 episode |

因此：**"状态差异 → 失败"这一因果链，本轮只完成了它的两端，中间最关键的一环（失败时刻的状态）
没有采到。** 任何"欧氏距离大所以失败"的说法在这里都是无依据的。

---

## 2. 为什么没采到（过程事实，不是借口）

1. Phase 2 筛查（发现两个失败）用的是 `oracle_hse`，**当时仪器还没做出来**（Gate D 在之后才通过）。
2. Gate B 复查这两个失败时，为了严格复现，命令与 Phase 2 逐项一致 —— **没有**加 `SHB_TRACE_JSONL`。
   这是有意的：先证明"可重复"，再谈"为什么"。代价就是这两个 episode 没有状态。
3. Gate D 的 trace 覆盖的是新 seed；而新 seed 上**没有出现失败**（`docs/10`）。

想补上这一环，最小代价是：**对 `4300003` / `4300000` 各跑 1 次带 trace 的 oracle_hse**
（2 次 rollout）。本轮预算（24）已用满，故未执行。

## 3. 现有可用的状态数据（只描述，不外推）

`results/phase3/analysis/desk_arrange_episodes.csv`（5 个成功 episode，cue/switch 两个时刻全字段）：

| 量 | 观察到的范围（成功交接） |
| --- | --- |
| cue 步 | 47–79 |
| cue→switch 延迟 | 1–15 步（office 上最长 39 步） |
| 切换瞬间 `action_cache_len` | 0（缓存已排空才切换） |
| 夹爪（cue） | 左 0.0–0.99、右 0.0–0.99（取决于第一阶段结束时状态） |
| 末端位姿 | 右臂 x/y/z 三档明显不同的位置（对应 5 个不同场景） |
| 切换后首个 action | 出现在 switch 同一步 |
| 切换后首次接触 | 出现在 switch 同一步（`contacts > 0`） |

**能说的**：成功交接的状态**并不唯一** —— 夹爪有开有关（切换瞬间右夹爪从 0.015 到 1.0 都出现过）、
末端位置分布很宽，说明策略对这些差异是鲁棒的（至少在这 5 个状态上）。
**不能说的**：失败状态一定落在这些范围之外。

### 3.1 一个**不完整**的失败侧样本（office_organize seed 4300000）

补跑时 trace 里留下了一段 seed 4300000 的**部分**记录（episode 被我们手动终止，未跑完，
**不计入任何成功率**），它的交接时刻状态如下（与 3 个成功 episode 对比）：

| seed | cue 步 | switch 步 | 物体（mouse）位置 @switch | 夹爪 L/R @switch |
| --- | --- | --- | --- | --- |
| **4300000（已知失败，部分记录）** | 41 | 48 | `[0.163, -0.007, 0.757]` | 0.992 / 0.021 |
| 4400005（成功） | 118 | 128 | `[0.236, -0.116, 0.815]` | 0.996 / 0.015 |
| 4400008（成功） | 44 | 48 | `[0.198, -0.015, 0.758]` | 0.996 / 0.484 |
| 4400009（成功） | 36 | 48 | `[0.155, -0.151, 0.743]` | 0.988 / **1.000** |

**观察**：没有任何一个状态量能把 4300000 和三个成功样本干净分开 ——
mouse 的 z 高度 0.757 落在成功样本 0.743–0.815 的区间内，夹爪开度也在区间内。
**这就是"没有状态差异证据"的具体含义**：不是"没算"，而是**算过之后看不出差别**。

（n=1 且该 episode 未跑完，只能当探索性观察，不能当结论。）

## 4. 下一轮最小可证伪干预（只做设计，本轮不实施）

### 干预 I（最便宜，零代码改动）：切换时机

- **做法**：对 `desk_arrange 4300003` / `office_organize 4300000` 各跑 `--clear_cache true`
  （官方配置项，立即切换）与 `false`（当前，延迟 1–39 步）各 3 次。
- **隔离的变量**：**动作缓存里的陈旧 A 动作**。
- **可证伪**：若 `true` 下失败率显著下降 → 失败与"用 A 的剩余动作执行 B 的开头"有关；
  若两种设置都失败 → 与缓存无关，指向状态或策略。

### 干预 II（需要一点脚本，但仍不改策略）：交接位姿回中

- **做法**：在 `switch` 发生的时刻（被动 hook 已能精确定位），调用环境**自带**的 mplib 规划器，
  把当前机械臂移动到一个**固定参考构型**（例如该任务第一阶段的 home 构型），
  期间**不换指令、不改策略、不动物体**；规划失败则记为一次失败（不重试）。
- **固定**：seed、物体布局、B 策略、切换时机、判据。
- **可证伪**：同一 seed 上，只改机械臂构型，若成功率从 0/3 提升到 ≥2/5 → 位姿是原因之一；
  若无变化 → 位姿不是主因（更可能是物体几何或策略自身）。
- **对照**：对**成功**的 seed 也做同样回中，检查是否把成功弄坏（负作用检查）。

### 干预 III（只改物体几何，作为对照）：固定机器人、移动目标物体

- 保持机器人交接位姿完全不变，只把目标物体沿某一轴平移 ±3cm，测成功率曲线。
- 作用：把"机器人位姿"和"物体几何"两个混杂因素**解耦**。
  `docs/09 §2.4` 已经指出 B0 与 A→B 的物体分布不同，这一干预是唯一能把两者分开的做法。

> 三个干预都**不需要训练、不需要改判据、不需要实现 Agent/DeCo**，且都能在现有代码里做。

---

## 5. 对"距离大所以失败"的明确拒绝

本轮**没有**做任何"状态欧氏距离 → 成功率"的拟合，也**不建议**做：
- 成功交接的样本只有 5 个，失败交接的状态样本是 0 个；
- 关节/末端空间的距离与任务成败之间没有先验的单调关系（同一个桌面位置，抓取方向差 90° 可能完全失败，位置差 10cm 反而没事）；
- 用 5 个成功点去拟合判别边界，必然过拟合。

下一轮若要做状态比较，**最小要求**是：失败状态 ≥3 个、成功状态 ≥3 个，且**同任务同 seed 族**。
